# Cleanroom reimplementation of GDAL 3.13.0dev unified `gdal` CLI

Oracle: /home/agent/oracle/executable (execute-only; GDAL 3.13.0dev-cbc00e6b71,
released 2026/06/11, trimmed build). Workspace builds `./executable` via
`./compile.sh` (make + g++, embeds spec/ files with .incbin).

## Architecture

- `spec/` : probed ground truth, committed. Generated by `tools/gen_spec.py`
  (dev-time only, runs the oracle). Contains per-command verbatim `--help`
  stdout (`help/*.txt`), stderr (`help/*.err`), `--json-usage` out/err
  (`jusage/*`), non-leaf error usages (`misc/*.errusage`), fixed outputs
  (`misc/version.out`, `formats.out`, `drivers.out`, ...) and the merged
  parse spec `tree.json` (args with aliases/shorts/positional parsed from
  help text + jusage metadata).
- `src/engine.cpp` : the whole CLI flow (see below).
- `src/handlers_*.cpp` : per-command behavior, registered by command id
  (path joined with `_`, root = "ROOT").
- `tests/run_diff.py cases*.txt` : differential harness, runs oracle+ours in
  twin sandboxes, byte-compares stdout/stderr/exit/files. THE dev loop.

## CLI flow (all empirically verified, see tests/cases.txt)

1. earlyConfigScan: `--config` handling quirks:
   - `--config` last token: 1x "key=value" error, exit 1.
   - `--config KEY` (no '=', nothing after): "key and value" error printed
     TWICE total (early scan once + general pass once), exit 1.
   - `--config KEY=VALUE` or `--config KEY VALUE`: set + consumed.
2. generalPass (sequential, first match wins): --version, --license
   (dynamic: $GDAL_DATA/LICENSE.TXT then ./LICENSE.TXT then builtin short
   text), --formats, --config, --debug LEVEL (sets CPL_DEBUG), --optfile
   FILE (tokenize with quotes + # comments; splice; missing file: special
   2-line error). BUG-COMPAT: --version/--license coming FROM an optfile =>
   SIGSEGV; --formats from optfile => tms warning + "double free or
   corruption (fasttop)" + SIGABRT. We emulate.
3. Tree walk: subcommand aliases (visible: vsi cp/ls/mv/ren/rename/rm/
   rmdir/del, dataset cp/ren/mv/rm/remove, raster neighbours; hidden:
   root translate->convert, raster warp->reproject, raster/vector
   translate->convert). Root extra subcommands not in jusage tree: convert,
   info. `gdal <existing-file>` => info shortcut. `gdal read ...` pipeline
   shortcut NOT implemented yet (bare `gdal read` = Unknown command).
   Unknown subcommand: Levenshtein suggestion over canonical child names
   (distance <=2, unique min, aliases NOT candidates) =>
   "ERROR 1: Algorithm 'x' is unknown. Do you mean 'y'?" (no usage, exit 1);
   else "ERROR 1: <parent>: Unknown command: 'x'" + captured errusage.
   Root arg mode when first token is an option: --drivers, --config=X
   (values ignored + "Warning 1: gdal: Configuration options passed with
   the 'config' argument are ignored", exit 0!), unknown option / stray
   positional errors.
4. Leaf parse mimics GDALAlgorithm::ParseCommandLineArguments:
   - --help/-h/--help-doc anywhere => help (stdout) + captured stderr, exit 0.
   - --json-usage likewise. Alias invocation substitutes name in first
     usage line / full_path (only) - error prefixes use CANONICAL name.
   - Unknown option "Option '--x' is unknown." ERROR 5 + short usage
     (usage-line + Try help). Short options combine only if boolean.
   - int/real parse errors: "Expected integer value for argument '--x',
     but got 'v'." (ERROR 5, prefixed, usage).
   - choices: case-insens; fail => "Invalid value 'v' for string argument
     'x'. Should be one among 'a', 'b'." UNPREFIXED, NO usage, exit 1.
   - min/max value: "Value of argument 'x' is v, but should be >= n"
     UNPREFIXED but WITH usage.
   - positional assignment: see engine assignPositionals; key cases:
     scalar missing => "Positional arguments starting at 'METAVAR' have not
     been specified."; unbounded list takes leftovers minus later needs
     (can take 0 with no error); min0 list => no positional error, later
     "Required argument 'x' has not been specified." (can be several, then
     one usage block).
   - input dataset args (input_flags has "dataset") are opened at end of
     parse: missing file => "ERROR 4: %s: No such file or directory" then
     usage; happens BEFORE mutex/required validation output.
   - mutex: "Argument 'b' is mutually exclusive with 'a'." (spec order:
     subject is the later arg in spec order).
   - leaf --config=K=V consumed by 'config' arg => values ignored +
     "Warning 1: <name>: Configuration options passed with the 'config'
     argument are ignored" after parse, before run.
5. tms_NZTM2000.json diagnostics: emitted when driver list/raster-tile
   machinery instantiated. Verbatim in captured .err files. Rules:
   GDAL_DATA set => no warning; file found via finder (GDAL_DATA then cwd)
   but invalid => "ERROR 1: Expected type = TileMatrixSetType" per
   occurrence. VALID tms file in cwd would change raster tile choices $
   help - NOT modeled.

## vsi group (implemented, differential-tested)

- list: readdir order (no sort), preorder recursion, --depth counts path
  depth; file target: as-typed name + QUIRK mtime shown as epoch 0 (json
  omits last_modification_date; text shows 1970-01-01 00:00); --abs joins
  abs(arg)+"/"+display (for file target duplicates: /abs/s/f/s/f - bug
  compat); json = CPLJSonStreamingWriter style: 2-space indent, ": " after
  keys, NO trailing newline, empty array "[]" inline. --tree only affects
  json: dirs {"name","entries"}, files bare strings; long+tree: full objects
  + "entries" key last. Dates gmtime (TZ ignored). Text long:
  "%s 1 unknown unknown %12llu %s %s".
- Progress bar = GDALTermProgress replica (progress.cpp). Single-file copy:
  callbacks per chunk => small file prints whole "0...10...100 - done.";
  failure: partial progress only + "Copying of %s to %s failed: ..." +
  target REMOVED (self-copy a.txt a.txt => a.txt deleted! bug-compat).
  Recursive copy prints "0" at start only. Dir-conflict:
  "copy: Cannot create directory X" (ERROR 3) after "0".
- sync: SHALLOW (only one level; subdirs mkdir'd but contents NOT copied -
  oracle behavior!). Progress: update((entryIndex+1)/entryCount) after each
  actually copied file (dirs and skipped files: no callback). File compare:
  copies unless exists && same size && dst mtime >= src mtime.
  Missing source: 2 errors ("%s does not exist" unprefixed, then prefixed).
- move: rename(2), into-dir supported, progress like single copy.
- delete: empty-dir rmdir ok without -r; "Cannot delete %s" otherwise.
- sozip: NOT implemented yet (create/list/validate/optimize).

### GTiff geokey -> CRS rules (ALL empirical, 211-code sweep passes)

- projected (3072=PCS):
  - base angular unit != degree (grads, French Lamberts): rebuilt: db WKT
    with CONVERSION name -> "unnamed", axis abbrevs " (X)" stripped, USAGE
    removed, ellipsoid rebuilt (below), reparse.
  - PCS 32601-32660/32701-32760 (WGS84 UTM): db object but ENSEMBLE ->
    proj_crs_get_datum_forced datum, applied TEXTUALLY at export time
    (wkt2 splice; projjson datum_ensemble->datum minus $schema/scope/area/
    bbox/id). DO NOT reparse spliced projected WKT: PROJ parser renames
    some conversions to "unnamed" (e.g. Pseudo-Mercator).
  - everything else (incl. ETRS89 UTM 258xx, 3857, NAD83 UTM): db verbatim.
- geographic (2048=GCS):
  - 4326, 4322 (well-known WGS) or dynamic datum frame (ITRF*, WGS84 G*,
    SIRGAS-CON; PJ_TYPE_DYNAMIC_GEODETIC_REFERENCE_FRAME): db verbatim.
  - else rebuilt: forced-datum splice (ETRS89), USAGE removed, ellipsoid:
    invf = a/(a-b) from proj_ellipsoid_get_parameters (metres), snap to
    298.257223563 if within 1e-7, semi-major printed in metres, unit ->
    metre; numbers formatted with PROJ WKT rule: %.15g, but %.14g if the
    string contains 10 consecutive '9's; then reparse (this reproduces
    oracle's exact doubles, e.g. GRS80 -> 298.257222101004).
- VerticalCSTypeGeoKey (4096) holding a geographic 3D code (4979):
  promotes; db object; axis mapping 2,1,3.
- oracle `raster create --crs EPSG:26591` (deprecated) writes the
  replacement PCS (3003) - create-side identification, remember for writer.

### info text details

- area of use: strip trailing '.'; if len > 40 BYTES cut at first " - ",
  else first ", ", else first ' ', + "...".
- projection type line: "conv, method", but method omitted when equal to
  conv after '-'->' ' normalization (3857).
- corner geodetic display: normalized crs_to_crs to geodetic base (degrees)
  THEN multiplied by base angular unit factor*180/pi regardless (grads:
  values *0.9 - GDAL quirk); geographic: raw coords * same factor;
  transform failure (non-finite) -> blank after projected coords.
- json doubles: json-c conventions; projjson embedded by re-parse keeping
  raw literals (json-c json_object_new_double_s behavior).

## GTiff writer + raster create (src/gtiff_write.cpp, handlers_raster_create.cpp)

All rules below verified byte-for-byte against the oracle (tests/diff_create.py,
150 cases green):

- Layout: header(8) + IFD at 8 (entries sorted by tag) + tag data blocks in
  libtiff write order (ByteCounts array, Offsets array, then per-tag data in
  IFD order for the rest; custom GDALMeta/PixelScale/TiePoint/GeoKeys/
  GeoAscii/Nodata AFTER standard tags) + strip/tile data. Everything fully
  CONTIGUOUS - no even-byte alignment padding anywhere (append mode is the
  exception: appended IFD starts even-aligned).
- Strips: rps = 8192/scanline (min 1) or BLOCKYSIZE. Tiles default 256x256.
- Fill semantics: pixels = burn value(s), else nodata, else 0.
  Trim rule for the LAST strip (rows = h-(n-1)*rps instead of full rps):
  trimmed when explicit non-zero burn (any codec), or nodata-fill with
  compression=none. NOT trimmed: zero fill (FillEmptyTiles path writes
  full-size strips) and nodata-fill with compression (blank block compressed
  once, blob reused for every strip). Tiles never trimmed.
- SPARSE_OK=YES: block data omitted (offsets/counts all 0) when fill bytes
  are all-zero OR equal to the nodata fill; only a burn differing from both
  writes data.
- ByteCounts tag type: LONG when 1 block or PACKBITS; SHORT for
  compression=none when max count <= 0xFFFF; SHORT for DEFLATE/LZW when
  raw+raw/4+2 <= 8192 (raw = full block bytes per plane); else LONG.
  Offsets always LONG. 317 (Predictor) always written for LZW/DEFLATE,
  value 1 when not requested.
- DEFLATE is libdeflate (system libdeflate.so.0), zlib wrapper, with level
  shift: ZLEVEL 6..9 -> libdeflate 7..10; 1..5 and 10..12 identity; default 6.
  ZLEVEL outside 1..12 -> two 'not recognised' warnings, clamped 1..9 style.
  LZW: exact libtiff state machine (verified on random+run data, 19/19
  strips). PACKBITS: exact libtiff port - note the LITERAL_RUN fold keeps
  BOTH bytes (op[-2]=op[-1], no shrink).
- Photometric: Byte 3band RGB(2); Byte 4band RGB + 1 ExtraSample(2, i.e.
  unspecified alpha? actually 2); other multiband photo=1 + zeros extras.
- Nodata tag 42113 ASCII %.17g (trailing NUL in count); non-representable
  nodata (frac on int type, out of range) -> 'Setting nodata failed' ERROR 1
  but the file is still created without the tag/fill.
- Burn clamps+rounds to dtype range (300->255, -5->0, 1.7->2).
- Geokeys: built from PROJ; angular unit code 9122 remapped to 9102; area of
  use 40-byte truncated in citation; deprecated EPSG codes swapped to
  non-deprecated replacement in Srs::fromUserInput with Warning (unless
  OSR_USE_NON_DEPRECATED=NO).
- PROFILE=BASELINE: no geo tags in TIFF; PAM .aux.xml with WKT1_GDAL
  (MULTILINE=NO OUTPUT_AXIS=YES - keeps AXIS nodes) + GeoTransform +
  metadata. PROFILE=GeoTIFF: geo tags in TIFF, metadata only in PAM.
  GDALGeoTIFF (default): all in-TIFF (GDALMetadata XML, double-escaped &).
- Datatype arg: choices list UInt8...; hidden alias 'Byte'/'byte' accepted
  (engine special case when choices contain UInt8).
- Engine: list args validate exact min/max count ('N values have been
  specified for argument X, whereas exactly M were expected.');
  <KEY>=<VALUE> metavar args require '=' in each value.
- tests/codec_test.cpp: standalone encoder harness (#includes
  gtiff_write.cpp; link ONLY cpl/util/srs/dataset/json/jsonc/jsonwriter
  objects to avoid duplicate main/embGet).
- JSON double formatting (fmtG16, geoTransform/proj:transform/computedMin/
  Max/offset/scale): integral doubles -> "<n>.0" (int64 shortcut); else
  %.16f with ONE truncation pass removing a trailing run (>=6) of
  identical '0'/'9' digits, allowing a single rounding-artifact digit
  after the run (e.g. 3.5999999999999996 -> 3.6, 1e-7 -> 0.0000001,
  1/150 -> 0.0066666666666667 [NOT round-trippable - not %g-based!],
  0.9999999999999999 -> 1.0, 2.9999999 stays). NOT shortest-round-trip.
  cornerCoordinates use trim7 (%.7f, strip trailing zeros) like
  wgs84Extent - 1.5000001 kept as-is (no run-trim there).
- Corrupt TIFF directory surface (libtiff emulation in tiff.cpp diags):
  * first IFD count unreadable -> "TIFFFetchDirectory:<path>: Can not read
    TIFF directory count" + "TIFFReadDirectory:Failed to read directory at
    offset N"; count==0 -> "<path>:Failed to allocate memory for to read
    TIFF directory (0 elements of 12 bytes each)" + same second line;
    entries truncated -> "...: Can not read TIFF directory" + second line.
  * first-IFD failure: errors prefixed "<basename>: ", NO 'not recognized'
    line, then usage block, rc=1 (openGTiff err="reported").
  * later-IFD failure: same texts WITHOUT basename prefix, open succeeds,
    info renders with pages found so far.
  * IFD loop: two Warning 1 lines (_TIFFCheckDirNumberAndOffset + 
    TIFFReadDirectory:Didn't read next directory...), 0x%x hex + (%u).
  * first IFD offset==0 -> plain 'not recognized' + usage (like non-TIFF).
- gdalinfo JSON --mm gate: computedMin/Max only added when
  CPLGetLastErrorType()==CE_None after compute; any earlier open
  warning/error (e.g. corrupt-IFD diags) suppresses them in JSON.
  TEXT mode --mm always prints the 2-space prefix line; on min/max
  failure the line is just "  \n" (4-space "  Computed Min/Max=" on ok).
- checksum: float/complex band types cast double->int with INT32_MIN on
  overflow/NaN/Inf (x86 cvttsd2si); integer types clamp to int32 range.
- PAM .aux.xml <SRS> (WKT) and <GeoTransform> loaded and override
  in-TIFF geo info (PROFILE=BASELINE files rely on this).
- Subdatasets (multi-IFD): SUBDATASETS domain + text block gated by
  --no-md in BOTH text and JSON.

## Stats / histogram / PAM (built, matching)

- --stats/--approx-stats/--hist implemented incl. PAM (.aux.xml)
  writeback, byte-identical to oracle (Statistics %.14g, VALID_PERCENT
  %.4g, HistMin/Max %.16g, insertion order fresh, sorted on reload).
- approx stats subsample by sqrt(nBlocks) block stride; sets
  STATISTICS_APPROXIMATE=YES; approx cache HIDDEN from display/STAC
  unless --approx-stats.
- Band order of operations (matches gdalinfo, incl. error order):
  cached Min/Max read -> --mm compute -> stats -> histogram.
  All-nodata: per band emits mm-fail, stats-fail, hist-stats-fail.
- JSON computedMin/Max omitted iff the compute itself raised any
  error/warning (cplErrorSeq() snapshot, NOT lastErrorType != None:
  open-time warnings like unsorted tags must not suppress them).
- Byte hist: 256 buckets -0.5..255.5, no stats needed. Non-byte: hist
  computes stats internally (cached afterwards), range min/max +-
  half-bucket; min==max -> 1 bucket. Fresh compute prints
  "0...10...20... - done." progress line; cached rerun does not.
- STAC raster:bands order: data_type, stats{minimum,maximum,mean,
  stddev}, histogram{count,min,max,buckets}, nodata, scale/offset,
  unit. stats gate == band-level haveStats (fresh --hist stats leak
  into cache but NOT into STAC); histogram from band ctx.
- JSON band stats via trim3 (%.3f trimmed); hist min/max %.17g-ish
  fmt17; text stats "  Minimum=%.3f, Maximum=%.3f, Mean=%.3f,
  StdDev=%.3f"; text hist "  N buckets from %g to %g:".
- Cached STATISTICS_MINIMUM/MAXIMUM show as "  Min=%.3f Max=%.3f "
  line even without flags.
- Unsorted IFD tags (libtiff TIFFReadDirectoryCheckOrder warning):
  first IFD -> TWO warnings (basename-prefixed, then unprefixed);
  each later IFD -> one unprefixed. The unprefixed ones are LAZY:
  emitted after argument validation (e.g. after the json+crs-format
  mutual-exclusion error), so they are queued on the dataset
  (deferredWarnings) and flushed in the handler just before render.
- Metadata domains model (GetMetadataDomainList emulation):
  domainOrder = creation order (IMAGE_STRUCTURE set at open, then
  GDAL_METADATA tag domains in doc order incl "" at its doc position,
  then PAM domains in aux doc order); AREA_OR_POINT is created LAZILY
  (after PAM) so a PAM-less default domain lists last. Final list =
  non-empty ordered domains (excl SUBDATASETS) + DERIVED_SUBDATASETS +
  SUBDATASETS if non-empty. Text shows "" as "(default)"; JSON raw "".
  AREA_OR_POINT exists ONLY if GTRasterTypeGeoKey(1025) present
  (==2 -> Point else Area), not for other geokeys.
- MDI ordering: PAM-loaded domains are SORTED by key and stay sorted
  (later inserts, e.g. STATISTICS_*, go to sorted position - CPL
  CPLStringList sorted-list semantics). Tag-based (GDAL_METADATA)
  domains keep doc order and later inserts append.
- --mdd: single value (not repeatable, engine dup error; no comma
  split). Lookup case-insensitive, heading/JSON key echoes the GIVEN
  spelling. "all" (case-insens) = domain list minus
  ""/IMAGE_STRUCTURE/TILING_SCHEME/SUBDATASETS/GEOLOCATION/RPC/
  DERIVED_SUBDATASETS. Text block "Metadata (<name>):" goes between
  default Metadata and Image Structure blocks; xml: domains print raw
  pretty XML + blank line. JSON: metadata obj order = metadataDomains
  (if --list-mdd), "", extras, IMAGE_STRUCTURE, SUBDATASETS. --no-md
  kills all of it in JSON but text still prints "Metadata domains:".
- PAM writeback: domains written sorted lexicographically ("" first).
  xml: domains rewritten as <Metadata domain=... format="xml"> with
  re-serialized tree. Band: Histograms first, then sorted domains.
  Tag-based (internal) metadata never enters .aux.xml.
- CRS text fallbacks: if CRS has no authority ID (custom WKT PAM,
  degenerate geokeys) text mode prints "Coordinate Reference System
  WKT:" + WKT2:2019. --crs-format WKT2|PROJJSON forces WKT/PROJJSON
  ("Coordinate Reference System PROJJSON:"); AUTO default; json format
  + non-AUTO crs-format -> handler error after open ("info:
  'crs-format' cannot be set when 'format' is set to 'json'"), rc 1.
  PROJJSON text = raw proj_as_projjson formatting; WGS84
  ensemble->datum swap done by TEXT SPLICING (Srs::projjson) to keep
  PROJ's number formatting byte-exact.
- Degenerate geokeys still yield a CRS (libgeotiff fallbacks),
  constants in gtiff_read.cpp: mt==2 -> GEOGCRS "unknown"
  (unretrievable WGS84 ellipsoid); mt==3 -> geocentric GEODCRS
  "unnamed"; mt==1 -> ENGCRS "unnamed" with metre axes; other/absent
  mt (any other geokeys present) -> ENGCRS with "unknown" units.
  STAC proj:epsg is null when CRS lacks an EPSG code.
- Rich user-defined geokey CRSs (PCS/GCS=32767 with projection/
  ellipsoid parameter keys) are NOT built - only the bare fallbacks.

## vector info (GeoJSON) - IMPLEMENTED (tests/diff_vinfo.py 840/840)

- src/ogr.{h,cpp} value model; src/geojson_read.cpp reader;
  src/handlers_vector.cpp text+json output. Default output = TEXT
  (raster info defaults json!). Only GeoJSON + ESRI Shapefile drivers in
  the trimmed oracle; openShapefile still a stub -> .shp NOT handled yet.
- Field type promotion, DAG (Kahn) property ordering, tz aggregation:
  naive value LOCKS field tz to unknown (plain "DateTime"); two distinct
  known tzs -> "(mixed timezones)" text + json "timezone":"mixed
  timezones"; consistent Z -> "(UTC)"/"UTC"; consistent offset ->
  "(+05:30)"/"+05:30".
- FID semantics (hard-won; see tests in /tmp/vj/t*.json id*.json):
  * mode from FIRST id-bearing feature: string/double/bool -> "id"
    String field (all id values stringified via spaced-serialize), fids
    = index-based auto. All-int ids with any negative -> "id"
    Integer/Integer64 field + FID Column=id + fids auto (retroactive).
  * int-fid mode: int id>=0 -> fid; string id -> fid 0; double/bool or
    missing -> auto. Auto = first free fid at or after feature index
    (silent). Explicit dup -> altered the same way + once-per-layer
    Warning "Several features with id = N have been found. Altering...".
  * OLMD_FID64=YES metadata when any id/fid > INT32_MAX (all modes).
- Deferred diagnostics: geometry parse errors/warnings NEVER fatal for
  FeatureCollection/Feature roots (feature gets null geom, rc0), and are
  emitted only when features are iterated: --features -> once; text
  --fid N -> full set once + target feature's diags AGAIN; json --fid ->
  NOT AT ALL (json --fid also omits the whole "features" member!);
  plain/json without features -> none; --summary -> nothing at all (also
  suppresses fid-dup warnings, which otherwise print in every
  non-summary mode). Bare-Feature root parses eagerly at open (diags in
  ALL modes incl summary). Bare-geometry root: parse failure IS fatal
  (diag + ERROR 4 Failed to read GeoJSON data + usage, rc1).
  Invalid coordinate reports EVERY bad component (x AND y).
- Layer geometry type/Z is STRUCTURAL: from declared JSON "type" names
  (counts even when coordinate parse fails) and raw nesting z-detection;
  GeometryCollection never contributes Z at layer level, but a 3D member
  promotes the WHOLE GC geometry recursively (z=0 fill) for WKT/json.
- Extent: any successfully parsed geometry (incl EMPTY) -> extent
  printed, empty accumulation gives (inf, inf) - (-inf, -inf); json
  writes bare Infinity/-Infinity tokens (json-c style).
- crs member equal to default (EPSG:4326 via any spelling, OGC:CRS84)
  -> treated as absent: default inline WGS84 WKT, no area-of-use line,
  mapping 2,1. All-3D geometries (no crs member) -> EPSG:4979.
- --fid not found -> stdout line "Unable to locate feature id N on this
  layer." rc0. --where NOT implemented (needs SQL eval; oracle emits
  full diag set x3 with --features --where!). --update/--limit etc:
  --limit implemented.

## vector info (ESRI Shapefile) - IMPLEMENTED (tests/diff_vinfo.py /tmp/vs 810/810)

- src/shape_read.cpp. Driver "ESRI Shapefile". Layer name = basename.
- DBF: header y/m/d -> layer metadata DBF_DATE_LAST_UPDATE=yyyy-mm-dd (json
  domain ""); SHAPEFILE domain (json only, via lyr.extraMdDomains):
  LDID_VALUE + (ldid==87 -> ENCODING_FROM_LDID/SOURCE_ENCODING=ISO-8859-1,
  else SOURCE_ENCODING=""); domain emitted with just SOURCE_ENCODING:""
  when there is NO dbf at all. ldid==87 -> latin1->utf8 recode of names and
  string values.
- Field types: N->(dec>0 Real; w<10 Int; w<19 Int64; else Real), F->Real,
  L->Int+Boolean subtype, D->Date(width10), else String. NULLs: N/F first
  char '*' or empty; D "00000000" or '*'; strings all-space. Real text
  formatting uses %.{precision}f when width>0 && precision>0 (not
  ogrFormatDouble). emitNullFields=true (unset -> explicit null in output).
- SHP: type%10 base (11-18 Z, 21-28 M); Point/MultiPoint/Arc->(Multi)Line/
  Polygon (shells CCW signed-area<=0; holes attached via point-in-ring to
  containing shell; orphan holes -> own polygons = organizePolygons
  ONLY_CCW). Layer geomType from header type; extent from header bbox;
  count from SHX ((size-100)/8) else DBF nRecords. DBF-only file:
  Geometry None(101), no geom field, count=nRecords, json summary

- .prj -> Srs::fromEsriPrj (srs.cpp): proj_create imports ESRI dialect.
  Compound "GEOGCS[...],VERTCS[...]" -> horizontal section only.
  Geographic: WKT1_GDAL export, strip AUTHORITY, Degree->degree, append
  AXIS[Latitude,NORTH],AXIS[Longitude,EAST], reimport, proj_alter_id(EPSG,
  gcs). Projected: strip AXIS pairs, reimport (conv params keep "Degree"
  capital), REBUILD base geogcs same as geographic path and graft with

## Pass c4 SS7.4: GeoJSON size-limit error position (geojson_read.cpp)

The OGR_GEOJSON_MAX_OBJ_SIZE "too complex/large" error position is NOT a
byte offset: the reference reports the streaming scanner's token-based
(line, character), and the check runs at every parser-callback ENTRY
before that callback's own bump. Rewrote the estimator as a
GeojsonSizeMeter threaded through streamingParseError (single pass, so
crossing-vs-syntax-error ordering is stream order). Event mechanics
(calibrated by threshold binary-search on the limit):
- limit = trunc(mb*1048576) bytes; <=0 or trunc==0 disables (so
  mb=1e-7 silently disables). Default 200 MB.
- fire when entry-est >= limit; report the scanner position AT that
  event: string/literal events fire after their completion (i.e. at the
  following byte), number events report the number's own start column
  (their delimiter is swallowed), '{'/'['/'}'/']' fire pre-advance;
  a number's swallowed ']'/'}' fires the End event at the number's
  column.
- feature elements of the root-object "features" array are metered
  (est=0 per feature; feature's own object free); End-callbacks check
  too, so a crossing on the feature's last token still fires at its
  closing brace.
Two SCANNER-level column rules found while calibrating (these fix
latent syntax-error position bugs as well):
- a string containing ANY escape sequence counts its full BYTE length
  (quotes included); escape-free strings count 1 character.
- a number's swallowed delimiter, when it is a newline, still advances
  the line counter (ch resets to 1).
KNOWN residual fine-structure (measured but NOT implemented; needs true
json-c internals emulation, weight ~[1]): per-event thresholds show
object bump 736 (we use 744), member bump 41 generally but 39 for
feature-level "type"/"properties" and geometry-level
"type"/"coordinates" (we use 32), value-strings declen+49 as member
values vs declen+56 as array elements (we use +56), ']'-terminated
numbers 40 vs ','-terminated 48 (we use 48), array bumps wobble
79/80/81 by context, EndArray-of-array-element ~7-9 (amortized
append pointers; we use 0). These cancel to ~176/coordinate-pair on
real docs: an 8.9MB single-line doc fires within 23 columns of the
reference (0.06%); small-doc/small-limit positions (the measured
divergence class) are byte-exact - verified on a 17-limit battery plus
escape/newline/ordering cases. All totals-based crossing counts from
the c2 calibration still hold.

## c4: directive 7.6 - vertical datum shift on reproject

- A compound (or 3-axis) CRS on either side of a warp promotes BOTH
  sides to 3D (proj_crs_promote_to_3D + crs_to_crs + normalize) and,
  for SINGLE-band sources only, adds the per-pixel geoid undulation
  (zAdd = -inverse.z with z=0 in) to the pixel values.
- The shift is EXACT per destination pixel: with a vertical member the
  whole transform bypasses the scanline approximator (x, y AND z; a
  lerped z shows up at 1e-14 in Float64 outputs, a lerped x/y at ~1e-4
  in Float32 bilinear). Nearest spec path: finalize(round/clamp) the
  shifted value BEFORE the nodata-collision compare; bilinear spec
  path rounds first, then shifts, then finalizes.
- Grid prediction: the same-horizontal shortcut (identity gt) still
  applies for the suggested grid, but --resolution/--size read RAW
  corner-sampled extents (21x21 FWD through the promoted op) with NO
  ps-snap - suggestedOutput now carries raw extents (haveRaw) when
  sameCrs && vertical. KNOWN RESIDUAL: --size with same-horizontal
  compound dst embeds the raw extent noise into the pixel size; the
  oracle's FWD sampling noise (~1e-10, CHAOTIC per point - the inverse
  vgridshift iteration perturbs lon/lat sub-nanometer) is not
  bit-reproducible by any op construction tried (crs_to_crs, factory
  ops, reversed op, promote variants, towgs84, 2-stage pivots, inset/
  pad/nsteps sampling variants). -tr passes because only the raw
  ORIGIN (minx/maxy) lands in the gt and those match bit-exact.
- Band unit: a vertical CRS dropped by the target copies the SOURCE
  BAND unit (reader synthesizes implicit "metre" from vertical keys;
  Band::unitImplicit suppresses the writer's UNITTYPE item when the
  unit merely mirrors the file CRS). An --src-crs override contributes
  NO unit. Compound-preserving warps keep the implicit unit unwritten.
- Photometric: a warped 3-band dataset only forces PHOTOMETRIC=RGB
  when band interps are actually Red/Green/Blue (warpProduced branch
  in convert), else MINISBLACK.
- geoDoubleOrphan RE-CALIBRATED (old "empty source window" rule was

--src-nodata semantics (decoded from probes, non-obvious):
- The LEVEL RANGE (dmin/dmax feeding interval/exp level generation and
  polygon-mode extra bucket) is ALWAYS computed masking by the
  band-declared nodata only. --src-nodata does NOT change the range.
- --src-nodata V swaps the marching absence value: pixels == V become
  absent; pixels equal to the band-declared nodata become ordinary
  VALID values (deep -500 spikes generate real crossings).
- Interval and exp-base levels are additionally CLAMPED to the masked
  range: emit level L only if dmin < L <= dmax (that's why a raster
  with min 10 never grows a fudge ring at level 10, and why srcnd
  leaves level sets untouched). FIXED --levels are NOT clamped: they
  fire below dmin happily.

Polygonize (-p): bucket assignment, ring geometry, MIN/MAX attr clamp,
and shapefile output are byte-exact on nodata-free rasters and on dsm
(hole nesting). c8 rewrote hull-edge emission (hullPieces: walk oa->ob
with interior on the left, split at level crossings, one bucket per
piece, verticals enumerate against the walk) and the scheduling law:
N/W hull edges and raster-border E edges emit ALL pieces before the
square's level loop; E/S pocket edges and S border edges emit the
enumeration prefix through the last piece with bucket <= maxSeg before,
the remainder after. That fixed the old c7 "ring direction" residual
class wholesale (227 flipped rings on dbig -> 0), fixed nA/n4-class
pocket micros, dsm at all intervals, and the MultiPolygon part-order
divergences that were really phase artifacts.

REMAINING residual (documented, suite-excluded): dbig/dgeo -p geojson

geometry differences - earlier "missing vertex" reports were %.9g

- Warp path: nearest picks floor(px + 1e-10); bilinear has two forms:
  scale <= 0.5 on either axis widens BOTH axes' triangle kernels

## vector sort (hilbert) - fully decoded
- Key: order-16 Hilbert index (wiki xy2d convention == FlatGeobuf bit-magic; verified identical) of envelope-CENTER cells.
- Cell mapping: `(uint32)floor(65534.0*(center-extMin)/extWidth + 0.5)` - scale is **65534** (not 65535!), halves round UP (not ties-to-even). Zero-width axis -> cell 0. Extent = union of feature envelopes per layer.
- Sort: **std::sort (UNSTABLE introsort)** on (key) with comparator `if(!a.has) return false; if(!b.has) return true; return a.key<b.key;` where has = feature has non-null non-empty geometry. n<=16 is stable (insertion sort) which is why sparse probes looked stable; dense sets scramble ties in libstdc++-introsort-specific order. Reproduce by literally calling std::sort with same comparator semantics (element type irrelevant).
- Keys compared at full uint32 precision (probed float-collision pairs: strict order kept).
- Dead ends ruled out: round/floor at 65535 or 65536 scale, FGB floor mapping, square normalization, 2^17 grids, level-mixing, float-cast keys, sum-not-halved centers. The "boundary at (k-0.5)*65536/65535^2" bisection artifact came from comparing non-tied keys (tie test can't distinguish key(P)<key(0)).
- Choreography: exists-before-layer checks, geometry-field per-layer validation, strtree method error, gdalg echo - see cases_sort.txt.

## Decoded semantics

### Create path
- Defaults: Float64, burn 255, nodata always written, PlanarConfig=1
  unless `INTERLEAVE=BAND`. Band count = max(burn list, init list, 1).
- Bounds: `--extent`, else layer extent (recomputed when the header has
  none). Zero-feature layer: "Cannot get layer extent". A layer with only
  empty geometries keeps an unset (inverted-sentinel) envelope: "Could
  not determine bounds" in both sizing modes. Size mode additionally
  rejects degenerate axes (`minX==maxX || minY==maxY`, e.g. single point
  or horizontal line); resolution mode accepts them and applies the
  half-pixel buffer to implicit bounds (skipped with `--tap`).
- Int64 nodata text: `%.17g` render then `strtoll` prefix (`5e18` -> "5",
  1.5 -> "1", nan -> "0"). UInt64 keeps the plain double text.
- Finalize failure reports "Cannot create <output>".

### Burning primitives (both paths)
- Bresenham lines walked from the later vertex; `--all-touched` uses a
  step-walker with epsilon nudge and incx slope; horizontal edge fills go
  left-to-right only; polygon AT adds intersect-only cells; 3d lines
  interpolate Z per step, constant-Z ring outlines for polygons; per-shape
  junction-skip dedup; `--add` accumulates with per-feature dedup and
  clamps through the band type on encode.
- c8 3d-walker laws (derived with an offline Python replay of the walkers
  fit ULP-exact against oracle Float64 output; each law pinned by fuzz
  batteries of 150-1200 cases at 0 fails, plus z3d/zclip suite pins):
  - Both walkers process the segments of each part LAST-TO-FIRST. Plain
    burns overwrite, so the earliest segment wins shared junction cells;
    that matters because each walk starts pristine on a shared vertex and
    ends there accumulated (ULP difference).
  - Bresenham add: forward-looking dedup instead - every non-first
    segment (j>1) skips its final Bresenham point, so the junction cell
    keeps segment j-1's pristine start value (loop bound `>= 1` instead
    of `>= 0`). Degenerate j>1 segments thus burn nothing in add mode.
  - AT vertical/horizontal specials ACCUMULATE the variant from a corner
    pre-add (`v = var + dV*(i0 - df0); v += dV` per cell), never
    recompute per cell. AT zero-length segments burn variantEnd once,
    except when sitting exactly on a row boundary
    (`iY <= floor(dfY - 1e-9)` guard).
  - AT clipping (general case, exact op order matters for ULP): skip the
    segment when both endpoints are above the top or below the bottom
    edge (strict <0 / >h, after L2R swap); clip dfX<0 forward along the
    segment; the RIGHT clamp `dfXEnd>w` also slides dfYEnd along the
    segment (`dfYEnd += (w-dfXEnd)*dfM`) - this changes the bit pattern
    of the later y-clips and decides edge-landing burn races; then the
    start advances to its top/bottom crossing (`(edge-dfY)/dfM`, variant
    in tow), and the end pulls back to its own crossing
    (`dfXEnd + (edge-dfYEnd)/dfM`, min-guarded). An upward exit through
    y=0 always lands exactly on 0.0 (`sY = iY-dfY`), so whether that
    landing re-burn fires is decided by the loop bound race with the
    clipped dfXEnd - do not "simplify" the clip order.
  - AT vertical/horizontal clip their low end before the accumulate
    (`var += (0-df0)*dV; df0 = 0`), with dV computed from the UNCLIPPED
    span.
- Attribute burning: string fields parse with strtod; failures warn once
  ("Failed to parse attribute value ...") and burn 0. Values that cannot
  be represented exactly in the (first) target band type warn once
  ("Attribute value ... cannot be exactly burned ..."); value text is the
  raw string for string fields, `%lld` for ints, `%.15g` for reals.
- `--invert` wraps everything in a synthetic outer ring (frame at
  -2..w+2/-2..h+2) and burns the complement; non-polygons warn "Ignoring
  non-polygon geometries in -i mode". Invert burns even when the layer
  has no geometries.

### Update path (`--update` / `--add`)
- Order: open target, SRS warnings, where filter, `-a` field lookup,
  geometry presence check, band checks, read, burn, in-place write.
- No geometries (after `--where`): bare progress, rc 0, no band checks,
  no file write.
- SRS: layer-with-SRS vs unknown-target (and the reverse) warn with the
  two fixed messages. Differing known SRSs reproject geometries into the
  raster CRS (PROJ crs-to-crs, normalized for visualization) before
  burning; equivalence via IsSame-flavor comparison.
- `-b` out of range: per bad band an ERROR5/ERROR10 pair; when band 1 is
  bad an extra ERROR5 and rc 1 before progress; otherwise "0" progress
  then a single RasterIO panBandMap error (first bad index), rc 1.
- Uncompressed targets are patched sample-by-sample in place; partial
  tiles additionally get their padding zero-filled (the reference writes
  blocks back from the cache, which only carries the valid window).
- DEFLATE (predictor 1) targets: every block is decompressed, patched,
  padding-zeroed (tiles), and recompressed. Codec choice mirrors the
  reference: libdeflate level 6 (system libdeflate remaps to 7) when the
  worst-case zlib bound fits the read buffer (largest original compressed
  block rounded up to 1KB), else classic zlib level 6. Blocks that do not
  grow stay in place; grown blocks append at EOF with offset/count tags
  rewritten. Create-path deflate always uses libdeflate.
- DEFLATE with predictor 2/3 targets are left untouched (no reference
  case reached; bailout preserves the input file).

## Pass c7 — engine parser laws refined off the zonal sweep (2026-08-02)

Zonal probing exposed two generic-parser divergences; the fixes went
through three rounds before the full battery stayed green. Final laws
(all differential-verified, engine.cpp):

- Choices are validated in TWO stages by arg arity:
  * SCALAR args: at value-parse time inside setValue, before checkRange
    and before the verb argValueCheck for that token (vector combine
    --add-extra-fields bogus must die with the plain "Invalid value"
    line, never reach combine's \x07 SQLITE argValueCheck).
  * LIST args: deferred to validateChoices(), which runs in validate()
    AFTER the verb preValidator and BEFORE pendingPosErr. First bad
    list arg (declaration order) reports EVERY bad value it carries,
    exit 1, no usage block. Evidence: zonal --strategy/--pixels (scalar)
    beat --stat (list) regardless of token order; --stat foo,bar reports
    both; zonal band<1 (preValidator) and --of NOPE (argValueCheck)
    outrank the stat choice error; a bare `--stat foo` with no
    positionals still reports the choice error, not the positional one.
- Declared mutex reports precede the missing-required reports (zonal
  --zones-band+--zones-layer with --stat absent prints mutex first,
  required second, one usage block). EXCEPTIONS wired as `lateMutex`:
  vector_info and raster_info keep the committed order (required → PV →
  mutex → sql/where special) because the info verbs enforce their
  exclusions handler-side (cases_ogrsql pins required-first for BOTH
  the declared sql×input-layer pair and the sql/where special);
  vector_create still sequences its own reports. Post-validators stay
  AFTER the required loop (mosaic pins required → exists-refusal).
- zonal output processing: an append+upsert conflict suppresses
  zonalStatsValidateOutput entirely (no ERROR4/refusal before the mutex
  line), but an unrelated mutex (zones-band×zones-layer) does NOT — the
  exists refusal still stacks before it. --append onto a missing output
  silently degrades to plain create (handler clears the flag).
- TRAP for probing: sequential oracle-then-mine probes in one dir leak
  state — the oracle's run creates the output, flipping the second
  run's exists/append semantics. Use distinct output names per binary.

## Pass c10 — /vsizip//vsitar/ over /vsistdin/ refuse WITHOUT reading stdin

Ship-blocker from adversarial invocation probing (open stdin pipes):
we buffered stdin for `/vsizip//vsistdin/...` names, blocking forever
where the reference exits 1 in ~0.03s. Root mechanism (GDAL
VSIArchiveFilesystemHandler::SplitFilename, all differential-verified):

- Non-brace /vsizip//vsitar/ names are split by scanning for a
  RECOGNIZED archive extension. No extension substring ANYWHERE in the
  name -> the name simply does not exist; the underlying file is NEVER
  opened/stat'ed. `/vsistdin/` contains no such extension, so all of
  `/vsizip//vsistdin/[...]`, `/vsitar//vsistdin[...]` refuse with the
  standard ERROR 4 missing-dataset choreography (usage, rc1) without
  touching stdin — even when a complete valid zip is piped in. Same law
  covers existing archive FILES without a recognized extension
  (`/vsizip/noext` refuses even though noext is a valid zip).
- Extension followed by '/' or end = archive boundary (old rule, kept).
  Extension substring NOT at a boundary (x.zip.gz) -> the WHOLE rest is
  the archive candidate (how /vsizip//vsigzip/x.zip.gz still opens).
- BRACE forms are exempt from the scan: /vsizip/{/vsistdin/}[/inner]
  DOES read stdin (blocks under an open pipe, succeeds on fed zip+EOF,
  Files: line shows the brace path verbatim). /vsitar/{/vsistdin/}
  likewise. /vsigzip//vsistdin/ (stream-decodable) also still reads.
- CPL_ALLOW_VSISTDIN=NO + /vsizip//vsistdin/: plain ERROR 4, NO 4x
  "disabled" spam (stdin handler never reached).
- Implementation: splitArchivePath returns bool; false (non-brace, no
  ext substring) is treated as nonexistent at ALL ten call sites
  (readWholeAny, vsiWriteWhole, vsiWriteGzipProperties, vsiExists,
  vsiIsDir, vsiListDir, vsiStat, vsiListDirInfo, vsiZipTouchArchive).
- Harness: run_diff.py grew `#stdinfile: <path>` (bytes from a
  setup-created sandbox file fed on stdin; sticky) because `#stdin:`
  cannot carry non-ASCII zip bytes. 20 pins at the end of
  cases_vsivirt.txt (closed-stdin refusals zip+tar raster+vector,
  fed-zip-then-EOF exit-1, brace-success boundary, ALLOW_VSISTDIN=NO).
- Open-pipe check (must stay green): `sleep 30 | ./executable raster
  info /vsizip//vsistdin/` exits 1 in ~0.02s (rc from timeout wrapper,
  not 124); gzip/brace/plain-stdin forms still block by design.
- NOT modeled (GDAL retries later ext positions when an earlier archive
  candidate fails stat): `/vsizip/a.zip/b.zip/c` where a.zip is a
  DIRECTORY — we stop at the first boundary; exotic, never probed red.
